# ADR-0004：理解层——离线优先的确定性抽取器 + 可选模型适配器 + 引用守卫

- 状态：已接受（MVP-3 落地）
- 日期：2026-10-10
- 影响范围：`asistent/understand/**`、MVP-3 验收、后续 MVP-4/5/6 对"结论来源"的依赖
- 关联需求：SPEC §835-840（MVP-3 验收）、§5.5、§6.2、§6.3、§7.4、§8.1、§8.2、§11.4、§12、§21.1、§21.2、§1064

## 背景

MVP-3 要把一封邮件/一份资料变成**可追溯的理解结果**：带语义的时间字段、待办、缺失材料、行动建议、回复草稿，以及需要用户回答的 `Question`。

这里有一个绕不开的诱惑：用模型来"理解"中文通知，代码最短、效果看起来最好。但项目对理解层有若干硬约束：

1. 设备（RK3588，`/usr/bin/python3` 3.10.12，**没有 pip**）必须能离线跑完整个理解层；
2. 用户不在场时 Agent 是无人值守的，SPEC §1064 明确要求"未设预算前禁止无人值守无限调用"；
3. 任何 `Fact` 必须能回到原文（SPEC §6.2、§7.4）——"看起来对"不是证据；
4. 结论会驱动后续的外部动作（回信、缴费、报名），错一个时间字段的**语义**（把"报名截止"当成"活动开始"）就会产生真实世界的错误；
5. 规则/模板会长期演进，所以"结论是哪一版规则给的"必须可答（换了规则，旧结论要能被识别出来）。

同时我们也不想把模型永久排除：本地小模型或远端模型在"读长通知、总结要点"上确实强，未来一定会用。

## 决策

1. **默认路径是确定性规则/模板抽取器**（`RuleBasedUnderstander` + `extract.py`）。
   - 纯标准库、离线可跑、零成本、**同一输入同一输出**（纯函数，无随机、无隐式当前时间）；
   - 抽取结果带 `rules:mvp3-1` 这样的 `producer`，规则升级后旧结论可被识别；
   - 规则以**声明式表**表达（`LABEL_RULES` / `REQUIREMENT_MARKERS` / `MATERIAL_MARKERS` / `NO_REPLY_MARKERS` / `DECLARATIVE_TIME_RULES`），可以被审阅、被测试逐条引用，而不是散落的行内判断。
2. **模型只作为可选适配器**（`ModelBackedUnderstander`）。
   - 后端与预算都必须**显式配置**，否则构造就失败：`ModelDisabled`（无后端）/ `ValidationError`（无预算、预算为 0）；
   - 预算守门：调用次数与花费双上限，超限抛 `BudgetExceeded` 并把 `blocked_reason` 写进调用日志，**任务停下等用户调整预算**；
   - 调用日志（次数/花费/tokens/上次时间/失败原因）是理解层自己维护的可观察状态；
   - 失败不伪装：没有回退实现就抛 `UnderstandError`；配了回退就退回规则抽取器，并把降级写进 `producer`（`model->fallback:...`）与 `warnings`。
3. **引用守卫对所有产出一视同仁**。
   - `Fact` 必须至少一条 `Citation`（`path` / `locator` / `content_hash` / `supports` 齐全）；引用经 `CitationRef.require()` 唯一入口构造；
   - 给不出引用的内容只能落成 `Inference`（`candidate_only`）或 `Question`；
   - **模型给出的结论同样受此约束**：模型输出里没有引用的条目会被降级为 `Question` 并留下 warning，而不是直接进 `Fact`。
4. **不猜**。语义不明的时间（`10月24日` 没说是报名截止还是活动开始）→ `Question`；值缺失（`报名截止时间：待定`）→ `Question` 且保留"字段存在"这一事实；跨资料冲突（同槽位两个不同取值）→ `Question`，并且**不产出可发送结论**（草稿候选不落库，已存在的草稿被标 `STALE`）。
5. **原始资料只读**。理解结果一律新建对象并引用原始对象；`SourceDocument` 的内容哈希与身份在处理前后不变。
6. **草稿只增不改**。`Draft` 是稳定容器，内容全在 `DraftVersion` 上；编辑产生新版本；恢复旧版本也产生**新版本**（不是指针回退）；审批绑定 `(draft_id, version_id, version_no, content_hash)`，审批历史版本直接拒绝。

## 理由

- 设备无 pip、无人值守、结论驱动外部动作——这三件事叠加起来，"默认走模型"等于把可用性、成本与正确性同时押在一个不可观测的组件上。默认确定性、模型显式开启，是唯一能让"离线可跑"和"敢用模型"同时成立的组合。
- 引用守卫把"可信"变成机器可检验的不变量（缺字段就构造失败），而不是"人看一眼觉得合理"。它是**唯一**能同时在规则路径和模型路径上生效的机制。
- 把"不明确"一律转成 `Question`，代价是多几次追问，收益是永不用猜的时间字段。MVP-3 的验收本身就是围绕"追问"设计的（§838、§840）。
- 恢复产生新版本而不是回滚，是因为审批与审计挂在版本上：如果恢复是回滚指针，历史审批会突然指向"另一份内容"，审批与内容就脱钩了。
- 规则集版本化让"理解结果是规则给的还是模型给的、哪一版"可答，为 MVP-6（成长资产/规则版本）留下接口。

## 被否方案

- **默认调用模型（哪怕只是本地小模型）**：设备离线不可用、无法给出零调用证据、且模型对"引用"的忠实度不可控，会把引用守卫变成事后补引用的形式主义。
- **把模型输出当事实、只做事后抽检**：违反 §6.2 的硬约束，且无法在无人值守时兜底。
- **用正则硬猜语义（例如"第一个日期就是截止"）**：在真实通知里必然出错，而且错得没有痕迹。语义靠标签证据（同句、窗口受限）+ 不确定就追问。
- **在 `Draft` 上原地改内容**：会让审批、审计、diff 全部失去锚点（§5.5 明确要求版本化）。
- **恢复 = 指针回退**：审批与审计绑定版本，回退会让"已批准的内容"被静默替换。
- **把冲突当成"取最新/取第一个"**：冲突恰恰是用户需要裁决的信息，自动选一个等于替用户做决定（§840 明确要求展示冲突并追问）。

## 影响与代价

- 规则集需要持续维护，覆盖面靠 fixture 与测试逐条锁住；不认识的写法只会变成 `Question`，不会变成错误结论（`warnings` / `unaccounted` 都要人工看）。
- 抽取层引入了两个存储实现都要满足的读法约定：**版本历史读存储里的 `DraftVersion` 对象，而不是 `Draft.version_ids` 反向指针**（写入时 `version_ids` 仍维护，供审计与阅读）。这条约定是实测发现的：SQLite 回来后 `version_ids` 为空，重跑会算成 v2 并再建一版同样内容（幂等被破坏）。判定与实现的依据写在 `drafts.py::versions_of` 的 docstring 里。
- 引用守卫让"模型输出缺引用"从静默接受变成显式降级 + warning，短期看像噪声，长期看是唯一能审计的路径。
- 冲突时把已存在草稿标 `STALE` 而不是删除：草稿的历史与审计需要保留，但"可发送结论"必须是零。

## 验证证据

- 默认路径零模型调用：注入"一旦被调用就抛错"的后端跑完整流程，后端调用次数 = 0（`tests/understand/test_model_guard.py::test_full_flow_makes_zero_model_calls`，原始输出见 `docs/mvp/mvp-3.md` 场景 5）。
- 预算守门：`max_calls_per_day=1` 时第二次调用抛 `BudgetExceeded`，后端总调用次数仍为 1（同上场景 5）。
- 引用守卫对模型生效：模型输出缺引用的结论只落成 `Question`（`test_model_payload_without_citation_becomes_question`）。
- 时间语义与不猜：`tests/understand/test_time_semantics.py`（14 项）、`test_extract.py`（16 项）。
- 冲突不产出可发送结论：`tests/understand/test_questions.py::test_conflict_has_no_sendable_conclusion`、`test_draft_from_before_the_conflict_is_marked_stale`。
- 草稿版本化：`tests/understand/test_draft_versions.py`（14 项）。
- 全量：`python -m unittest discover -s tests -t .` → `Ran 403 tests ... OK (skipped=5)`；设备 `/usr/bin/python3` 3.10.12 复跑见 `docs/mvp/mvp-3.md`。

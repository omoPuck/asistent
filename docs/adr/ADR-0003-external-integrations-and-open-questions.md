# ADR-0003：外部接入策略与开放项（邮件 / 百度网盘 / 模型 / 手机入口）

- 状态：**部分待用户确认**（默认假设已可支撑开发，真实链路验证前必须确认）
- 日期：2026-10-10
- 影响范围：MVP-2、MVP-3、MVP-4、MVP-5、MVP-7、MVP-8
- 关联需求：R-008、R-013、R-022、R-023、R-024、R-025、SPEC §18 门、§20

## 决策（默认假设，可被用户指令覆盖）

1. **邮件（邮件门）**：以标准库 IMAP/SMTP 实现「受控邮件连接器」；开发与验收先用**脱敏夹具**，
   真实账号接入前必须由用户在本机/设备本地填写授权码（不进对话、不进 Git）。
   连接器契约（身份、去重、文件夹移动、Message-ID 冲突、游标失效）用夹具回归覆盖，不因缺真实账号而停摆。
2. **百度网盘（网盘门）**：`asistent/pan/` 定义 `PanClient` 协议，随包提供 `LocalDirPanClient`（本地目录模拟远端，供契约/闭环测试），
   真实实现（开放平台 OAuth 或既有登录态通道）先做 Spike 验证认证/上传/列举/回读校验/恢复，再切换；未验证前不宣称真实网盘能力已交付（§1.3、§21.3）。
3. **模型（执行后端）**：默认 `EchoBackend` 保证离线可测；真实模型经 `HttpChatBackend`（OpenAI 兼容端点）接入，
   密钥只从受保护配置读取。用户设定的每日费用/调用预算未配置前，禁止无人值守无限调用（§21.7）。
4. **手机入口（默认）**：设备内网 Web/PWA + 口令/令牌认证，标准库实现，不依赖第三方消息平台；
   若用户选择消息工具（Telegram/钉钉/企微/飞书）或邮件控制面，只替换控制面适配层，审批与幂等语义不变。
5. **认证与审批分离**：聊天文本中的「同意/发送」不构成审批；审批必须由认证控制操作绑定「动作 + 规范化摘要 + 版本」（§21.2、§21.3）。

## 待用户确认项（阻塞真实链路，不阻塞契约与原型）

| 编号 | 待确认 | 影响 | 默认处理 |
|---|---|---|---|
| OQ-1 | 首条流程用哪个邮箱、何时提供 IMAP/SMTP 授权码 | MVP-2/3/5/8 真实链路 | 先用夹具，账号就绪再切 |
| OQ-2 | 百度网盘接入方式与凭据（开放平台 OAuth / 既有登录态） | MVP-7 真实归档 | 先 LocalDirPanClient + Spike |

| OQ-5 | 模型供应商/路由与每日预算上限 | 理解与草稿质量、费用 | 默认后端可插拔，预算未设则限流 |

## 影响与代价

- 用夹具先行可以在没有真实凭据时完成契约、幂等、审批、归档闭环的全部可测部分；
  但**验收报告必须区分**「夹具等价验证通过」与「真实链路验证通过」，不得合并宣称（§18 末段、§21.9）。

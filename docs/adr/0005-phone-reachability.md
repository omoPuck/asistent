# ADR-0005：手机侧可达性——为什么用 Tailscale tailnet，而不是"让手机进内网"

- 状态：**已被 ADR-0006 取代（2026-10-23）**——改为 frp 内网穿透到自有阿里云 frps。
  本方案的技术分析（为什么"让手机进内网"不可行、为什么不能直连）仍然成立，保留备查；
  若将来不想依赖自有服务器，可回到这里的 tailnet 方案。
- 相关：ADR-0002（开发/部署拓扑）、ADR-0003（外部集成与待确认）、SPEC §控制台、ADR-0006

## 背景（实测事实，不是设想）

1. 板子在**公司内网** `192.0.2.0/24`（`192.0.2.10`），出口经堡垒机；手机在**移动数据**上，
   两者之间没有任何直连路径。
2. 开发机虽然有个 `192.0.2.2` 的地址、看起来"同网段"，**直连 `192.0.2.10:18090` 超时**——
   同网段编号不等于同一段物理网络。这条差点被误判成"能直连"。
3. 板子出网是**部分放行**的：`baidu` 通、`api.openai.com` 被拦。
   所以"加个隧道"必须先验，不能假设（实测：Tailscale 的控制面/DERP/apt 源**全部可达**）。
4. 手机侧要的是能装出带离线壳的应用，而 **Service Worker 需要安全上下文**：
   明文 HTTP 下只能"添加到主屏幕"，拿不到离线壳。

## 决策

**板子作为一个节点加入 Tailscale tailnet，用 `tailscale serve` 以 HTTPS 暴露控制台；
手机装同账号的 Tailscale 客户端，从任意网络访问。**

具体：

- 板子上跑官方 `tailscaled`，`tailscale up --accept-dns=false`。
  **不接管板子的 DNS**（减小爆炸半径：板子仍用 `127.0.0.53` 解析内网名字，
  加隧道不该动内网解析）；
- `tailscale serve --bg https / http://192.0.2.10:18090`：TLS 在尾巴上终止，
  控制台本身不改协议——**不改控制台代码就能拿到安全上下文**；
- 手机与板子的访问控制交给两层：tailnet ACL（限定只有本人设备）+ **控制台令牌**（已有）。

## 为什么不选另外几条路

| 方案 | 为什么不选 |
|---|---|
| 手机连进内网（VPN 进公司网） | 让 24h 的手机常驻公司内网，攻击面比"板子单向加入一个 mesh"大得多；而且离开公司就断 |
| 仅同局域网（把板子接家里网） | 是**未来**形态，但现在板子在内网、手机在移动数据，解决不了当下；且 on-call 场景人本来就在外面 |
| 开发机当跳板（SSH 转发） | 已在用，**作为过渡手段保留**，但它把可用性绑在那台笔记本上（会休眠），与"24h 常驻"矛盾 |
| 内网穿透类（frp/cloudflared，自建中转） | 要么需要一台公网机器，要么依赖第三方；Tailscale 的访问控制与证书是现成的，自建等价物成本更高 |

## 安全边界（诚实写清）

- Tailscale 是**出站建立**的加密 mesh：板子不向公网开放任何入站端口；
  外部唯一能触达它的路径是**你 tailnet 内的设备**。
- 因此风险集中在一处：**tailnet 账号若被攻破，攻击者可到达控制台**——此时仍需控制台令牌，
  但令牌是第二道门而非唯一一道。建议在 admin 控制台加一条 ACL，
  只允许手机这一个节点访问板子，而不是"整个 tailnet 都能访问"。
- 令牌纪律不变：只在 `~/asistent-var/config/console-token`（600），不进仓库/日志/对话。
- 板子的内网出口仍然只用于出站；**不因为加了隧道而放开任何入站规则**。

## 后果

- 新增一个**运行时依赖**：`tailscaled` 必须在板子上常驻，否则手机侧不可达
  （控制台本身照常在局域网内工作，不因隧道故障而失效——依赖是单向的）。
- `/etc/resolv.conf` **不动**（`--accept-dns=false`）。
- 手机侧拿到 HTTPS 域名后，PWA 可真正安装（含 Service Worker 离线壳）。
- 验收影响：AT-08 的"手机独立发起/看状态/答追问/编辑/审批"从"局域网内"扩展为"任意网络"；
  这不改变契约（审批绑定、令牌、离线重连语义都不变），只改变**可达路径**。

## 待确认（需要人操作）

1. 在 tailnet admin 控制台开启 **HTTPS Certificates**（否则 `tailscale serve` 无法签发证书）；
2. 建议同时开 **MagicDNS**，这样手机侧用的是稳定域名而不是会变的 IP；
3. 建议加一条 ACL 把板子节点限定给手机节点（见上"安全边界"）。

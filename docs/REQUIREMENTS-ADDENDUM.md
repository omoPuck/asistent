# 需求增补与已确认裁定（相对 SPEC.md v0.4）

> 本文件记录**用户已明确决定**的事项与由这些决定推导出的实现约束。
> SPEC.md 仍是规范性正文；凡本文件与 SPEC.md 冲突处，以本文件为准（用户裁定优先），
> 并由 Lead 在契约/文档中同步体现。

## A-1 邮件门（已定：复用 Windows 侧同一套 `mcp-email-server`）

- **裁定（用户）**：复用已安装的 `mcp-email-server` 通道，不新建邮箱侧方案。
- **实测修正**：开发机与设备**无直连**（设备无法 TCP 访问开发机），所以"复用 Windows 上那台服务"不可行；
  改为**在设备上本地运行**同一个 `mcp-email-server`（同版本 v1.11.1、同工具集），
  这才是"复用同一套通道"在设备拓扑下的可行解释。
- **设备实测**：venv 安装成功（54 包全 aarch64 wheel、零编译、无 sudo）；
  stdio 握手返回 `serverInfo={"name":"email","version":"1.11.1"}`，`tools/list` 19 个工具；
  IMAP 实测走到"认证失败"⇒ 链路通、只缺凭据。
- **凭据约束**：设备侧 keyring 后端为 `fail`（无 SecretService），**只能明文配置文件**；
  因此凭据落在 `~/asistent-var/config/`（700/600，仓库外），
  **绝不**进入对话、仓库、Git、日志、审计、argv。
- **首阶段策略**：先只读同步（不启用发送）；发送能力在 MVP-5 审批链路就绪后再开。

## A-2 网盘门（已定：复用已连通的 `baidu-drive` skill / bdpan 通道）

- **裁定（用户）**：复用本地已连通的百度网盘 skill，不新建开放平台应用。
- **Spike 结论**：条件可行；`bdpan` 为 Go 自包含二进制，官方有 linux-arm64 构建，
  SHA256 与 skill 内置校验值逐字节一致；认证是 OAuth 授权码（OOB）模式，首次授权必须用户本人完成。
- **已执行**：在 `board` 上用 skill 自带安装器（`--yes`，内置 SHA256 校验）安装 **bdpan 3.8.7**
  → `~/.local/bin/bdpan`（`/home/asistent/.local/bin/bdpan`，ELF aarch64，静态链接）。
- **调用约束**：服务按**绝对路径** `~/.local/bin/bdpan` 调用（不改用户 dotfiles、不动 PATH）；
  长驻服务加 `--no-check-update` 避免 CLI 自更新打断 24h 运行。
- **未解决 U-1（最关键）**：无人值守 token 自动续期未实测。若不能自动续期，
  必须在手机端**显式提示"需重新授权"**并降级，不得假装通道可用。

## A-3 手机门（已定：设备常驻内部 Web/PWA + 口令/令牌认证）

- 控制台绑定设备内网地址，端口从 18080–18100 选空闲端口（18080 已被占用，实测 18090 可用）；
  必须带认证（口令/令牌）后才允许访问，不得裸奔在内网。

## A-4 部署拓扑（已定）

- 开发在开发机，部署目标为 `board:~/code/asistent`（`receive.denyCurrentBranch=updateInstead`）；
  运行数据在 `~/asistent-var/`（700，仓库外，不随 push 覆盖）。

## A-5 **构建即发布**（用户新增要求）

- **要求（用户原话）**："把产物放到百度网盘的步骤，应该构建的时候就做掉。"
- **含义**：归档不是事后人工补的动作，而是**构建/发布流程的一个步骤**：
  构建产物在生成后由构建流程自动完成"快照 → manifest → 上传 → 逐文件哈希回读校验 → 记录归档状态"。
- **实现约束**：
  1. 必须有一个可重复执行的发布入口（命令/脚本），把"产物上传到网盘并校验"作为一步；
  2. 该步骤必须幂等：同一 `archive_id` 重跑不重复上传、复用已校验对象，内容变化才派生新 id；
  3. 部分失败必须留下 `ARCHIVE_PENDING`/`PARTIAL` 状态与逐文件清单，可重试且只补传失败对象；
  4. 结果未知（上传中崩溃/超时）不得盲目重传，必须先 stat/回读判定；
  5. 凭据不参与构建流程的日志输出。
- **归属**：MVP-7（归档通道落地）与集成阶段。

## A-6 归档/恢复的验收口径（用户已确认）

- 归档与恢复必须**容错且可升级**：错配、部分失败、哈希不一致等状态必须**可见且可重试**，
  不允许"要么全成功要么静默丢"。

## A-7 中文检索与时钟（由设备实测推导，已写入契约 v0.2）

- 中文检索必须走应用层切分（`asistent/contracts/search.py`），不得依赖 FTS5 `unicode61` 原始分词。
- 时钟不可信（回退 >300s）时**拒绝写业务时间戳**并降级上报（`asistent/contracts/clock.py`）。
